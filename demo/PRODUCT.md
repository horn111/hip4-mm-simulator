# Product

## Register

brand

## Platform

web

## Users

The primary visitor is a Hyperliquid Builders Program reviewer evaluating the
project quickly on desktop. Secondary visitors are HIP-4 market-making builders
who want to inspect the execution assumptions before installing the package.

## Product Purpose

Explain in under 90 seconds how an observed L2 queue, an aggressor trade, and a
virtual passive order produce a conservative partial fill. Success means the
visitor understands the causal model, trusts that the displayed values come
from the Python engine, and opens the repository or the validation report.

## Positioning

HIP-4 MM Simulator makes paper-execution assumptions visible and reproducible:
market access belongs to SDKs; this project focuses on queue-aware execution
simulation.

## Conversion & proof

- Primary CTA: run the six-event sample replay.
- Secondary CTA: open the 24-hour mainnet validation report.
- Memorable line: See exactly when a HIP-4 paper order earns a fill.
- Belief ladder: understand the queue model, see one causal fill, verify the
  invariant checks, then inspect the source or report.
- Proof: the committed sample fixture, its SHA-256, the v0.2 release, the PyPI
  package, and the published 24-hour aggregate validation report.

## Brand Personality

Precise, candid, and inspectable. The interface should feel like an engineer's
carefully prepared evidence surface: calm enough to read quickly, dense only
where the mechanics require it, and explicit about model boundaries.

## Anti-references

No crypto-hype landing page, profitability dashboard, dark trading-terminal
costume, generic SaaS card grid, decorative gradients, glassmorphism, or
unverifiable hero metrics.

## Design Principles

- Show causality before aggregates.
- Put reproducibility next to every important claim.
- Use real fixture values and clearly separate them from 24-hour evidence.
- Treat limitations as part of the product, not fine print.
- Keep the primary path understandable without installation or live services.

## Accessibility & Inclusion

Target WCAG 2.2 AA, support keyboard-only use, 200% zoom, touch targets of at
least 44px, color-independent state labels, and reduced-motion preferences.
